## Feed 地址

The feed is generated by GitHub Actions and deployed as static assets to the `wrtbox` Cloudflare Pages project:

```text
https://wrtbox.pages.dev/openwrt-25.12/stable/<apk-arch>/packages.adb
```

The router downloads the signed index and public key from wrtbox Pages. GitHub Actions keeps the unchanged official sing-box prebuilt binary, re-signs its APK container with the feed key, and uploads the APK to the configured domestic server.

## 路由器安装

### Stable 通道

The feed installer detects the OpenWrt release and architecture, installs the
signing key, writes the APK repository, and refreshes the package index:

```sh
wget -O - https://wrtbox.pages.dev/feed.sh | ash -s stable
```

The installer removes existing wrtbox entries before adding the selected
channel. Other feeds, including momo, are left untouched.

Then install from SSH if desired:

```sh
apk add sing-box
```

Or open LuCI **System → Software**, click **Update lists**, search for
`sing-box`, and install or upgrade it there.

### Beta 通道

Beta follows the newest official prerelease returned by GitHub. That may be
labeled alpha, beta, or release candidate upstream.

```sh
wget -O - https://wrtbox.pages.dev/feed.sh | ash -s beta
```

### 手动配置

```sh
apk add ca-bundle
wget -O /etc/apk/keys/wrtbox.pem https://wrtbox.pages.dev/public-key.pem
ARCH="$(cat /etc/apk/arch)"
echo "https://wrtbox.pages.dev/openwrt-25.12/stable/${ARCH}/packages.adb" \
  >> /etc/apk/repositories.d/customfeeds.list
apk update
apk add sing-box
```

## Feed 工作方式

The installer currently supports OpenWrt 25.12, including ImmortalWrt 25.12.
When a new OpenWrt series is published, the feed workflow and installer can
be extended to add that series without changing the existing 25.12 URL.

The default feed builds aarch64_generic and x86_64 for stable and beta. The feed index and signing key are hosted by wrtbox Pages. Signed APK files are served from the domestic server configured as WRTBOX_SERVER in the workflow; stable and beta files are separated under /stable/ and /beta/. GitHub Releases remain as an archive and fallback copy.

Stable follows the latest official GitHub release. The two channels use
release tags that include the APK package revision (for example
`sing-box-v1.14.4-r0`), matching apk's `${version}` expansion in the index
URL. The workflow reads that revision from the APK metadata, so a future
`r1` or `r2` is handled automatically. The feed path continues to
distinguish the stable and beta channels.

## 迁移 APK 服务器

The migration script prepares a fresh Ubuntu server with Nginx, rsync, the
`/srv/wrtbox/stable` and `/srv/wrtbox/beta` directories, and the static download
configuration. It is intended for an occasional server replacement, such as
changing the server once a year. Run it from a machine that can already SSH
into the new server:

```sh
chmod +x scripts/setup-server.sh
ssh-keygen -t ed25519 -f ~/.ssh/wrtbox-actions -N ''
scripts/setup-server.sh NEW_SERVER_IP ubuntu ~/.ssh/wrtbox-actions.pub
```

Store the private key as a Base64 GitHub Actions secret:

```sh
base64 < ~/.ssh/wrtbox-actions | tr -d '\n' | \
  gh secret set WRTBOX_SSH_PRIVATE_KEY_B64 --repo Oterea/wrtbox
```

Then change the single WRTBOX_SERVER value near the top of
.github/workflows/update.yml, commit, push, and trigger the workflow. Test
the new server before using the feed:

```sh
curl -fIL http://NEW_SERVER_IP/stable/sing-box_<version>_openwrt_aarch64_generic.apk
```


The script does not copy the old APK files. After the workflow runs once with
the new address, it repopulates the new server. Keep the old server available
until that run succeeds, then remove its old `/srv/wrtbox` data when convenient.
If the migration must be rolled back, restore the previous `WRTBOX_SERVER` value
and the previous Actions SSH secret, then run the workflow again.

The script does not configure HTTPS or a domain; the APK is verified by the
APK/feed signing key, while Pages continues to serve the signed index and
public key.

## 支持范围

The default workflow publishes OpenWrt 25.12 packages for `aarch64_generic`
and `x86_64`, which cover the common ARM and x86 soft-router platforms.
Other architectures can be enabled by adding them to the matrix in `.github/workflows/update.yml`; the same official SDK and APK naming rules must
be available for that architecture. OpenWrt 24.10 is not included because it
uses opkg/IPK rather than APK. New APK-based OpenWrt series can be added as
another matrix branch after their SDK and feed mapping are available.

## 安全说明

The repository contains only public workflow code and the feed public key. The APK signing private key and Cloudflare credentials must be stored as GitHub Actions secrets and must never be committed.
